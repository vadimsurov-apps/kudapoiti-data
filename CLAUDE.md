# Данные приложения «Куда пойти с детьми» (Москва и Подмосковье)

Владелец — Вадим (не программист, Telegram @Vadim_Surov). Общение на русском, коротко и честно.

## Что здесь лежит
- `places.json` — места для приложения (приложение скачивает его с GitHub). **Генерируется** из `data/kuda-poiti-mesta.xlsx`
  командой `python3 tools/xlsx_to_json.py data/kuda-poiti-mesta.xlsx places.json`. Руками places.json не править.
- `deals.json` — акции/скидки/пробные занятия. Приложение показывает только действующие (`until` ≥ сегодня или пусто).
  Поля: id, place_id (id места из places.json), kind (trial|free|discount|birthday|promo), title, details, code, until, url, checked.
- `icons/<id>.png` + `icons/index.json` + `icons/versions.json` (хэши — приложение перекачивает перерисованные) — иконки новых мест (с 692-го), приложение скачивает их само.
  Исходники SVG — `icons-src/`. Рендер: `python3 tools/render_icons.py <id> ...`.
- `auto/candidates.json` — кандидаты в места из OpenStreetMap (робот, раз в неделю).
- `auto/promo-snippets.json` — фразы про акции с сайтов мест (робот, каждую ночь). `new: true` — новое/изменилось.
- `tools/` — скрипты: `batch_helpers.py` (функция P для строки таблицы), `add_batch14.py` (пример партии),
  `draw_icons.py` (svg, s, eye, face, sparkle, O), `icons_batch14.py` (пример рисования), `MetroStations.swift` (метро).

## Правила
- **Картинки никогда не повторяются**: у каждого места свой сюжет иконки (не перекраска чужой).
  ПЕРЕД рисованием обязательно открой (Read) ВСЕ листы `icons-catalog/sheet-*.png` и выпиши себе сюжеты, похожие на
  задуманные. Повтором считается тот же предмет/животное/персонаж, даже в другом цвете или позе (уточка, кинокресло,
  божья коровка, зебра, компас, пазл, воздушный змей, дракончик, домик, ведёрко, термометр, яйцо, кубики, сокол — уже заняты).
  Если сомневаешься — выбери другой сюжет. После рисования — `python3 tools/make_catalog.py` и посмотри новые иконки
  рядом со старыми. 5 ноября ночной запуск повторил 12 сюжетов из 20 — их пришлось перерисовать.
  Исключение: дворовые площадки и катки (пока не добавляем вообще).
- Акции — только детско-семейные, с источником-страницей. Не брать: устаревшие («продлена на сентябрь»),
  для пенсионеров/студентов/участников СВО, взрослые бары, спам казино/букмекеров со взломанных сайтов.
- Места — только детские/семейные, работающие. Координаты из OSM ставить с `Точность координат = точно (OpenStreetMap)`.
- Не дублировать места: проверять по названию и расстоянию < 300 м.
- Коммит → `git pull --rebase` → push в main. В конце коротко отчитаться: сколько мест и акций добавлено/снято.

## Категории фильтра (колонка «Категории», через запятую)
parks, playcenters, trampolines, amusement, ropes (верёвочные парки), climbing (скалодромы), karting, skate (скейт-парки,
памп-треки), спорт по видам: martial (самбо, дзюдо, борьба, карате, бокс), football, racket (падел, теннис, бадминтон),
gymnastics (гимнастика, акробатика), ballgames (баскетбол, волейбол), hockey (хоккей, фигурное катание), chess,
sport (прочие секции), dance (танцы и балет), quests, museums, science, shows, cinema, masterclass, tours,
animals, water, pools, transport, winter, food. Категории `active` больше нет — не использовать.
Сейчас мало мест в dance и спортивных секциях: в candidates есть dance (100) и sports_school (94) — брать в приоритет после кафе.

## Ежедневная работа (запускается по расписанию)
0. Замок `auto/lock-daily` (как у роботов пополнения). Ежедневный робот правит основную таблицу и deals.json; новые места пишет в `KP_PART=fun`/`cafes`/`sections` только если соответствующий замок свободен, иначе — в основную таблицу.
1. Снять просроченные акции из deals.json; для акций с checked старше 30 дней — перепроверить страницу (WebFetch).
2. Из `auto/promo-snippets.json` (new: true) выбрать реальные детские акции:
   - если место уже есть в places.json — добавить акцию;
   - если нет — добавить место (строкой в xlsx через tools, данные из auto/candidates.json) + уникальную иконку + акцию.
3. Цель — до 100 новых мест с иконками за запуск; приоритет: места с акциями, затем **кафе и рестораны с детской
   комнатой** (cat kids_cafe в candidates; категория в таблице — food; Вадим просил сделать на них упор), затем бассейны/
   секции/игровые центры/музеи/театры. Детскую комнату у кафе подтверждать по сайту/описанию, иначе не добавлять.
   В OSM кафе с детской мало (112, в основном сети: Чайхона №1 — 58, «Лепим и варим» — 16, «Андерсон» — 13, «Урюк» — 12),
   поэтому дополнительно брать списки филиалов с детскими комнатами с официальных сайтов сетей (WebFetch): «Андерсон»,
   «Чайхона №1» (детская есть не везде — проверять по странице филиала), «Урюк», Kitchen, Jooie, Ribambelle, «Тануки» и др.
   Координаты филиала — из OSM, если есть; иначе адрес с сайта и `Точность координат = приблизительно`. Сначала качество, потом количество.
4. Перегенерировать places.json, отрендерить иконки, обновить index.json, `python3 tools/make_share_pages.py` (страницы «Поделиться» p/<id>/), проверить, что JSON валиден и число мест ≥ прежнего.

## Сайты: НЕ спрашивать Вадима
Роботы работают без людей. WebFetch по адресу, которого не было в результатах WebSearch, требует подтверждения
Вадима — так делать нельзя. Порядок:
1. Тексты сайтов кандидатов и сетей уже скачаны: `auto/pages/<ключ>.txt`, оглавление `auto/pages/index.json`
   (ключ кандидата = `osm-<type>-<id>`, например osm-node-123). Сначала искать там (Grep по auto/pages).
2. Нужен сайт, которого нет в кэше, — дописать адрес в `auto/fetch-queue.txt` и запушить: Action `sites.yml`
   скачает его за несколько минут (к следующему часу точно будет).
3. Прямо сейчас нужна страница — WebSearch, затем WebFetch ТОЛЬКО по ссылке из результатов поиска.
4. Если подтвердить не удалось — место пропустить, а не спрашивать.

## Роботы пополнения (каждый час, три параллельных — каждый со своей областью и своими файлами)
| робот | KP_PART | что добавляет | сюжеты иконок |
|---|---|---|---|
| cafes | `cafes` | кафе и рестораны с детской комнатой (food) | еда, посуда, кухня, сладости |
| sections | `sections` | танцы и секции по видам спорта (dance, martial, football, racket, gymnastics, ballgames, hockey, chess, sport), детские бассейны | спортинвентарь, форма, музыка и танец |
| fun | `fun` | игровые центры, батуты, квесты, верёвочные парки, скалодромы, картинг, музеи, театры, мастер-классы, животные, парки и прочее | игрушки, животные, сказочные персонажи, транспорт, природа, космос |

Правила для каждого робота:
0. **Свой замок** `auto/lock-<робот>` (время UTC ISO). Если моложе 75 минут — предыдущий запуск ещё идёт: выйти.
   Иначе записать, закоммитить и запушить сразу. В конце удалить тем же коммитом, что и данные.
1. Писать новые строки ТОЛЬКО в свою таблицу `data/parts/<робот>.xlsx`: запускать скрипты с `KP_PART=<робот>`
   (batch_helpers.SRC тогда указывает на неё). Основную таблицу и чужие таблицы не трогать.
2. Коммитить ТОЛЬКО свою таблицу, `icons-src/<id>.svg` своих мест и `icons-src/subjects.txt`. places.json, icons/*.png,
   index.json, страницы p/ и каталог собирает GitHub Action `build.yml` сам после пуша — их не коммитить
   (локально собрать можно: `python3 tools/build_all.py` — для проверки).
3. Дубли: перед добавлением проверить places.json и ВСЕ data/parts/*.xlsx (название + < 300 м).
4. Иконки: прочитать все листы icons-catalog и `icons-src/subjects.txt` (реестр сюжетов: строка «id — сюжет»).
   Выбирать сюжет только из своей области (таблица выше), которого нет ни в каталоге, ни в реестре; дописать в реестр.
   Если при `git pull --rebase` в subjects.txt оказался такой же сюжет у другого робота — свой перерисовать.
5. Цель — 100 мест за запуск, качество важнее количества (работающие, детские, с адресом; детская комната у кафе —
   подтверждённая). Меньше 100 качественных — так и написать. В конце одна строка: сколько добавлено по категориям.
6. Пуш: `git pull --rebase` → push; при конфликте в своей таблице такого быть не может (она только твоя), в subjects.txt —
   объединить обе версии строк.
